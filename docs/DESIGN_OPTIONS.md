# DESIGN OPTIONS — 첫 외주 상품 4안

| 안 | 형태 | 고객 사용법 | 장점 | 단점 | 판정 |
|---|---|---|---|---|---|
| A | Excel 수식형 | 파일 열기 | 설치 없음, 가장 단순 | 규칙 확장/테스트 자동화에 약함 | 보조 아이디어 |
| B | Python/EXE 실행형 | 파일 2개 선택 후 실행 | 확장성, 재현성, 테스트 용이 | CLI만 제공하면 비개발자 진입장벽 | **채택** |
| C | 로컬 웹형 | 브라우저 업로드 | UX 친숙, 확장성 좋음 | 첫 상품치고 개발량 큼 | 보류 |
| D | 폴더 감시형 | 지정 폴더에 파일 저장 | 반복업무 자동화 강함 | 초기 설정/오작동 통제 필요 | 보류 |

## 최종 선택

**B안을 핵심 엔진으로 채택하고, 그 위에 얇은 Windows GUI를 추가한 형태로 확정했습니다.**

```text
Python validation core
├─ CLI entry → excel-validator-cli.exe
└─ GUI entry → excel-validator-gui.exe
```

이 방식은 웹서비스까지 만들지 않으면서도 비개발자에게는 `파일 선택 → 검증 실행` UX를 제공합니다.

## 선택 이유

- 외주 첫 상품의 범위를 작게 유지할 수 있음
- 핵심 검증 로직을 GUI와 CLI가 공유함
- pytest/CI로 재현 가능한 검증 가능
- Windows EXE로 Python 설치 없이 전달 가능
- 이후 고객 요구가 생기면 CSV/DB/API 등으로 확장 가능

## 중지선

현재 MVP에서는 웹앱, DB, API, 설치프로그램, 코드서명을 추가하지 않습니다.
실제 외주 고객의 요구가 확인될 때만 다음 설계 사이클에서 다시 4안을 비교합니다.
